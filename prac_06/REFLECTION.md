## What have you changed about your process in this subject based on your personal reflection?

I have shifted from writing code by trial and error to planning my program structure first. For example, I now separate my code into logical functions (SRP) and think about data structures (like using dictionaries for counting) before typing. I also started using the PyCharm debugger and reading tracebacks carefully when I encounter errors, rather than just guessing.


## What do you still need to change in terms of your approach, application, time on task, attitude, etc.?

I still need to improve my time management. I tend to leave the practical work until the last minute, which reduces the time I have to deeply test the code. I also need to get into the habit of testing edge cases (like empty inputs or invalid types) rather than just testing the normal "happy path."


## What are you doing well in the subject so far that you will keep doing?

I am doing well at keeping my code clean and readable by following PEP 8, using meaningful variable names (like `colour_to_hex` instead of just `data`), and utilizing f-strings for formatting. I also successfully commit to Git regularly, which prevents me from losing progress and makes tracking my changes much easier.

## What do you need to stop or change in your work for this subject overall so far?

I need to stop copying and pasting code without fully understanding it. When I refactor, I should type things out manually to build muscle memory. I also need to stop using bare `except:` blocks; I must specify the exact exception (like `ValueError` or `FileNotFoundError`) to avoid hiding real bugs.
